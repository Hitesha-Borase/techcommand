# Academy migration generation evidence

`drizzle/0030_biomedical_academy.sql` is an additive dual-track migration: eight new tables, no business data, roles, rates, credentials, clinical results or qualifications seeded. Its legacy filename does not limit the `track` columns to Biomedical.

The normal generator encountered an existing duplicate-parent history conflict in snapshots 0012/0018. Existing migration history was not edited. An isolated temporary Drizzle workspace generated a snapshot from the exact baseline `ad54c3c4e4488e0429ce5ab8b65367d56851ae1f` schema, then generated the delta from the changed schema with the existing installed Drizzle version. These two generated snapshots retain that evidence. The resulting delta was copied as migration 0030 and the existing journal was appended once. Regression databases apply every SQL migration in sequence with foreign keys enabled.

Never deploy either snapshot as a replacement for prior production migrations; only the new additive SQL/journal entry belongs to the migration stream. The tables are `academy_families`, `academy_profiles`, `academy_training_records`, `academy_signoffs`, `academy_signoff_evidence`, `academy_authorizations`, `academy_supervision_reviews` and `academy_experience`.

The same isolated history generated `0002_snapshot.json` and the next delta, copied as `drizzle/0031_academy_progression.sql`. It adds only `academy_policies`, `academy_requirements` and `academy_advancement_reviews`. No career thresholds, rates, promotions or live business records are seeded. All prior SQL migrations and snapshots remain unchanged. Requirements and requested-review snapshots are versioned; management decisions do not alter payroll or equipment authorizations.

The next isolated generation produced `0003_snapshot.json` and `drizzle/0032_spinlife_closeout.sql`: only `spinlife_closeout_drafts`, preserving separate recoverable billing preparation and the immutable handoff source snapshot. It does not seed accounts, financial records or business transactions. The existing canonical QA/invoice/payroll tables and approval rules are reused.

`0004_snapshot.json` / `drizzle/0033_dme_experience.sql` makes only the experience `family_id` nullable, allowing real QA-approved DME service evidence to be recorded without guessing an equipment category. Drizzle generated the exact full-column copy/rebuild/index sequence. Its foreign-key OFF/ON pragmas were replaced by D1-supported transaction-local `defer_foreign_keys` ON/OFF; [Cloudflare's official constraint documentation](https://developers.cloudflare.com/d1/sql-api/foreign-keys/) was verified September 19, 2026. No table references `academy_experience`; all prior row fields, signed snapshots, primary/foreign keys and unique replay indexes are copied intact. A dedicated regression seeds prior biomedical evidence, applies this migration in a transaction with foreign keys enforced, verifies byte-equivalent row values and checks retained constraints. No historical experience is reclassified or backfilled.
